# 项目概览与定位

> **本文回答**：Deepseek Science 是什么？做什么、不做什么？目标用户和核心场景是什么？

> 状态：已定（方向已对齐）

---

## 一句话定位

**Deepseek Science 是一个本地优先的科研 AI 工作台**：全新的 Rust 后端内核 + 全新的 React 前端（DeepSeek 视觉风格）+ 全新的 Tauri 桌面壳，以 **Deepseek** 系列模型为主力，支撑文献调研、数据分析、数学建模、代码实验、论文写作与长程自主研究——所有工具执行与数据留在本地，仅 LLM 推理走云端。

## 工程原则

本项目从零设计、从零实现，所有代码自行编写。设计原则：

| 维度 | 本项目决策 |
|------|----------|
| 工程关系 | 全新独立工程，代码全部自研 |
| 后端 | **从零用 Rust 实现**（agent 内核、工具系统、HTTP/SSE 服务） |
| 前端 | **从零用 React 搭建，DeepSeek 风格主题** |
| Tauri 壳 | **从零实现**进程守护 / 端口注入 / 系统集成 |
| 模型定位 | **以 Deepseek 为主力**，保留 OpenAI 兼容抽象 |
| 数据格式 | SQLite，全新 schema（`dss.db`） |
| 契约 | **自行设计** HTTP + SSE 契约，按本项目需要定义 |

**原则**：本项目设计上采用经过验证的成熟形态——agent 循环、工具语义、SSE 事件流、前端布局均按通用最佳实践自行设计实现。代码全部从零编写，契约按本项目需要自行定义。价值在于：原生 Rust 内核（性能 / 内存安全 / 并发 / 单文件部署）+ DeepSeek 原生集成 + DeepSeek 风格 UI + 日志等新能力。

> 决策：本项目自行设计需求规格、行为与回归基线，不依赖外部代码基。设计上遇到取舍时，按本项目的实际需要决策；任何重要偏离登记到 [09 决策记录](decisions.md)。

## 范围边界

### 做（In Scope）

1. **全新 Rust 后端内核**：agent 主循环、frame 状态机、工具系统、skill 加载、MCP 客户端、记忆系统、Rolling Compact、验证子系统、artifact 存储、LaTeX 编译——设计自行定稿，代码从零。
2. **自行设计的 HTTP + SSE API**：端点与事件流按本项目需要定义（见 [04 API 契约](api-contract.md)）。
3. **全新 React 前端**：从零搭建，DeepSeek 视觉风格（蓝色 / 超级简约 / 细线条，见 [10 设计系统](design-system.md)），覆盖对话 / 工作区 / 论文预览等场景。
4. **全新 Tauri 桌面壳**：从零实现进程守护、端口注入、系统集成。
5. **Deepseek 深度集成**（增强方向之一）：主力模型、reasoning_content 流式利用、长上下文策略、（待调研）多 agent / 并行推理。
6. **实验与数据分析强化**（增强方向之二）：更安全的代码沙箱、数据可视化产物、可复现实验记录。
7. **文献与知识图谱**（增强方向之三）：检索、引用网络、本地知识库与 RAG。
8. **长程自主研究**（增强方向之四）：无人值守长任务循环、状态文件化、故障恢复。
9. **跨学科扩展**：插件化的学科数据处理与可视化（化学/生物/地学/材料等，**需调研**，见 [07](domain-plugins.md)）。
10. **日志列表**——新 App 必备：前端可浏览的统一日志视图（系统日志 + agent 执行记录）。见 [11 日志系统](logging.md)。

### 不做（Out of Scope，至少初期）

1. **不引用任何外部项目代码**。所有代码独立编写。
2. **不做云端 / 多用户 / 协作**。保持本地优先、单用户。
3. **不追求与历史数据二进制兼容**。数据导入走显式转换工具（可选，详见 [05](data-model.md#迁移)）。

### 灰区（待定，登记追踪）

- **代码执行沙箱方案**：科研用户需要可执行的代码（Python/R 等）。我们以 Rust 重写后端为契机引入真沙箱，但方案（子进程隔离 / WASM / PyO3 嵌入 / 容器）影响很大，**待调研定案**。见 [02 技术栈](tech-stack.md#代码执行沙箱) 与 [06](enhancements.md#实验与数据分析)。
- **是否保留 Python 工具生态**：科研用户大量依赖 Python（pandas/sklearn/matplotlib）。完全去 Python 不现实，需决定「宿主语言 Rust + 受控 Python 子进程」的具体形态。

## 目标用户与核心场景

**用户画像**：科研工作者、研究生、独立研究者——需要在本地完成文献综述、数据分析、建模、实验、论文写作，且重视数据隐私与可复现性。

**核心场景**：

1. **对话式科研助手**：自然语言提问 → 调用工具（文件、代码、检索、MCP）→ 流式呈现过程。
2. **文献综述与论文写作**：分级文献召回 → 引用图扩展 → DOI 校验 → 结构化写作 → LaTeX→PDF 编译（Tectonic）。本项目的论文写作 skill 链自行实现。
3. **数据分析与实验**：在受控环境跑 Python/R、生成图表、记录可复现的实验谱系。
4. **长程自主研究**：无人值守循环，文件化状态、stall 检测、guardian/worker 分离。
5. **学科专用工作流**：分子可视化、地理数据、材料结构等（插件化，待调研）。

## 非功能目标

| 目标 | 本项目目标 |
|------|----------|
| 启动速度 | 原生二进制，**亚秒级冷启动** |
| 内存占用 | 目标 **<50MB 常驻** |
| 部署形态 | **单静态二进制**（无运行时依赖） |
| 并发 | tokio 多线程，工具可并行 |
| 内存安全 | **编译期保证**（Rust ownership） |
| 二进制体积 | 目标 **<20MB**（strip + LTO） |

> 决策：选 Rust 作为后端宿主语言，原生二进制带来启动/内存/部署/并发的整体收益。相比 Python 等解释型语言在常驻内存与启动上有数量级优势，代价是科研生态弱（通过受控 Python 子进程补齐，见灰区）。
